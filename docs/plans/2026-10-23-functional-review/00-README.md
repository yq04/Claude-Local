## 当前结论

统一查询、逐账号指纹校验、去重和真实观测时间的方向成立，且已有分层合成测试。当前证据不足以把候选称为“无明显问题、可直接覆盖”的版本：已确认本地部署遗漏在线脚本/扩展、全批次网络等待持有身份事务锁且无法取消；独立复核还发现在线路径复用的旧 Python 归档读取存在认证结束帧检查缺陷，并会提取查询不需要的项目记录。主计划给出这些问题的修复边界及最小验收，不以放宽身份校验换取表面成功率。

长期可查询也需要补齐授权生命周期。失效的静态授权和已关闭的保存账号浏览器资料，无法通过刷新频率自然恢复；统一查询不等于永久免登录。应维持统一入口，增加集中恢复队列和明确的能力诊断，而不是让用户退回逐卡手动查询。账号有独立网络路由时，还需明确在线查询使用何种有效出口，不能把身份指纹匹配等同于网络隔离或防关联保证。

## 功能优先顺序

先修复候选交付与最小归档读取，再闭合批次状态、取消和两阶段提交；随后改进统一查询的授权恢复、运行环境/路由能力诊断及真实通路验收。项目级新增功能按 02 与 04 的收益排序推进，已经实现的搜索、排序、命令面板、TSV导出和时区统计不重复列为待开发。

全项目的高收益方向包括：CLI未安装时的首次接入引导、将浏览器资料联动与窗口启动偏好分开、显式按稳定账号ID配置用量历史归属、系统环境修改前的基线记录与受控恢复，以及有用户口令认证外层的保险库备份和新目标恢复。它们分别改善首次使用、日常切换、统计可信度和长期数据可恢复性；不以清空恢复标记、按账号名称猜归属或混淆网页/CLI登录态作为捷径。

## 审查与验证边界

审查对象为 `HEAD=92751ab1f71188fd21badcde687f60f0660fbb50` 之后的未提交工作区，包含新增的在线查询及浏览器扩展文件；已安装版本仍为0.1.8。现有 HANDOFF 记录历史交付，新的额度实施记录按末尾日期演进段理解。
