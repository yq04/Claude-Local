# 安全加固、养号增强与环境监控方案（源码校准版）

核查与修订日期：2026-10-30。基线为 `main` 分支（当前检出），`feat/free-warming-profiles` HEAD 为 `ec3d345`。本目录已完成源码级二次审计与修正，消除初版中的 API 误判与设计陷阱。

## 研究与校准范围

1. **GitHub 开源项目对比**：分析 10+ 个 Claude 多账号管理、环境安全、防封号工具，提取可借鉴设计。
2. **X/Twitter 社区经验**：抓取并交叉验证 6 篇防封号帖子原文，分层评估可信度（官方实锤 / 行业反欺诈通用逻辑 / 社区玄学证伪）。
3. **项目内部源码级二次审计**：核对每项拟议改动的真实 Rust/TypeScript 签名、数据结构与 UI 尺寸约束，排除已被历史版本修复的假缺口（S01/S02/S03/S11），修正 `probe()` 返回值、备份校验白名单与 Kill-Switch 非阻断恢复语义。

## 核心结论

1. **Claude-Local 在核心安全维度已领先同类开源工具**（`BAGAID01` 加密归档、确定性指纹种子 + 默认真实硬件渲染防反爬检测、20+6 项风控核验、四阶段养号、窄缓存维护），补充按需激活的**伴侣浏览器断线保护（Kill-Switch）**与**养号卡国家/时区一致性监测**即可形成完整运行时闭环。
2. **断线保护（F1）采用“仅浏览器运行期按需守护 + 零后续阻断”设计**：
   - 仅当受管伴侣浏览器窗口打开时才进行后台守护，浏览器关闭时零外网探测、零开销；
   - 网络抖动、超时或公共 API `HTTP 429` 限流绝不误杀，仅在确认 TUN 掉线直连或出口国家连续漂移时关闭受管伴侣浏览器窗口并告警；
   - **绝不锁死后续使用**：用户重新点击打开浏览器或点击“知道了”即自动解除告警并恢复托盘图标，绝不触碰系统网卡/路由，绝不中断 `claude.exe`。
3. **DNS `strict-route` 修复（F2）尊重 Clash Verge 三层配置架构**：在风控核验页提供分层修复向导（一键复制 Merge 覆写配置片段 + 立即复核闭环），避免盲写生成层 YAML 被客户端覆盖。
4. **保险库备份扩展（F6）全链路打通**：同步更新 `collect_files`、`allowed_backup_path`、`verify_staged`（含 `browser_bindings` 引用完整性校验）、`verify_rescue_staged` 与 `identities_backup_restore_new`，安全纳入 `warming_cards.json` 与 `manual_subscriptions.json`。
