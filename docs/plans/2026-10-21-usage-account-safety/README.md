# 使用体验与账号安全优化方案

日期：2026-10-21。基线：0.1.3，提交 `17779eaa5ce880b531ad3d8be5de691995d7e4f8`。状态：用户已授权按推荐方案实施；v2 增补额度问题与导航顺序，实施验证进行中。

## 建议先做什么

优先让“查看状态不会改历史”“备份保留原始内容”“隐私开关覆盖所有展示入口”成为可验证的产品行为，再完善危险操作提示、失败恢复和浏览器核验边界。当前已存在加密、路径限制、进程检查、恢复标记和回滚机制，应在这些机制上补缺口。

本轮调研完成了源码与目录说明核查，并查阅 Claude Code、Anthropic、Tauri 和 Microsoft 官方资料。没有读取真实凭据、保险库或用户会话，没有运行应用、测试、安装卸载或发布。

## 最值得处理的发现

- **S01，查看与修复混在一起。** 身份列表在旧摘要补齐的特定分支调用 `Store::open`；后者在进程已停止、无待恢复事务时可能改写会话。应拆开状态读取与工作区维护。
- **S02，保留历史不等于原样保存。** 当前保存前及恢复后都可能执行会话改写，部分内容块会移除，未见独立、持久的原件或逆向映射。“无损保留”不能作为当前实现的承诺。
- **S03，隐私覆盖不完整。** 单字符邮箱不会被打码；切换确认框直接插入目标邮箱；伴生起始页没有继承主程序隐私设置。
- **S04，危险操作和恢复说明可以更准确。** 直接删除当前身份前缺少其他弹窗已有的进程明细，恢复弹窗没有清楚展示将恢复的原身份。
- **S05–S07，状态需要说明来源和时效。** 离线额度重置属于推算，旧浏览器检测结果不能长期表示当前环境已核验；部分帮助和统计文档与实际页面不一致。
- **S08–S11，补边界与验证。** 回环桥已有随机令牌等保护，可进一步限制请求来源；跨进程争用和崩溃恢复需定向合成验证；安装器仍需一次性 Windows 环境实测。

这里的 P0/P1 是实施顺序，不表示已发生账号泄露、资料损坏或服务端封禁。

## 两项需要明确的产品取舍

### 历史处理：推荐原样保留

推荐 A：保留原始历史和账号归档；打开页面、补齐摘要、单纯备份都不修改 Claude 会话正文。跨账号保留的旧会话不自动改写组织、邮箱、签名、工具块或遥测相关记录。若旧会话不能跨账号继续，说明原因并提示新建会话，不承诺无感接力。

这是有意调整现有行为：可以减少无感历史改写，但某些依赖原有转换逻辑的跨账号续接可能不再成立。已有归档不会批量重写，历史文件不会自动删除，已有用户的保留选项不会被静默重置。

B 是继续维持旧的共享历史转换。它需要独立确认原件保存、失败回退和支持的 CLI 格式，不能与“保证账号安全”绑定。本方案不推荐把 B 作为默认实施范围，也不新增或强化规避检测、篡改遥测的能力。

### 隔离方式：先改善当前模式，目录隔离另做试点

推荐保留当前默认工作区管理模式，完成本方案的保护和提示。官方文档已提供 `CLAUDE_CONFIG_DIR` 多目录登录方式，但它是未来 CLI 隔离模式的候选，不能直接替换现有 Desktop、浏览器、归档和切换逻辑。

可选试点只使用新建临时目录与虚构数据，先查明配置、会话、CLI 登录及 Console 特例的真实边界，再另交设计；不迁移现有账号、不修改当前终端环境。

## 推荐批准的范围

批准“推荐方案 A”表示可以依次实施计划中的阶段 0–5：

- 拆分读路径与维护路径，原样保存历史，收敛自动会话改写。
- 统一主程序、确认弹窗和伴生页的隐私展示。
- 补齐进程明细、恢复原身份、离线推算及检测时效提示。
- 定向补充恢复、部分失败和并发保护；加固回环桥，清点无界面消费者的原生命令。
- 在一次性环境验证安装器；若环境暂不可用，明确保留该未验收项。

目录隔离试点、DPAPI/主密码体系、归档格式升级、强制更换密钥、大规模依赖替换不包含在上述批准内。真实账号验证、本机真实安装卸载、部署与发布也不包含在内。

## 验收底线

查看页面不改变默认 Claude 工作区；备份可证明保留输入原件；隐私模式不在正文、提示属性或无障碍名称中暴露完整邮箱；危险操作继续使用现有确认和原生复查；失败不能伪装成完成；旧归档、账号 HMAC、稳定 ID、浏览器种子及 SQLite v3 保持兼容。

测试只用虚构数据和隔离上下文。开发与验收不结束正在运行的 `claude.exe`。额度采集继续由 Python 单独写账本，不写 `.claude.json`、不增加 OAuth 轮询或刷新频率。
