# 0.1.2 加密存储兼容加固

本次修复备份验证失败后的私有暂存残留，并限制异常归档的解包资源消耗。保留 `.baga`、`BAGAID01`、`CLBKUP01`、AES-256-GCM、PBKDF2-HMAC-SHA256 600,000 次参数及旧 gzip / 当前 Zstd 读取；不迁移或重新加密已有归档，不更换主密钥、账号 ID、HMAC、SQLite v3 或浏览器种子。

核心归档协议继承自 CCBaga；0.1.1 的编码器与核对的固定版本一致。0.1.2 调整了自有缓冲的内存管理，磁盘格式保持兼容。全库口令备份及相关读取、恢复和权限集成由本项目独立维护，原版权声明继续保留。

## 已落实

- 备份快照及验证暂存目录由独占创建的操作对象持有。验证失败、后续恢复失败和正常异常展开时，清理本次操作自己的暂存目录；不扫描或删除旧用户目录。
- 成功生成的备份或恢复副本保留其验证结果。暂存清理失败显示独立诊断，不把成功副本误报为损坏；错误提示不含密钥、内容或临时路径。
- 普通归档在解包前检查声明大小、成员数量、路径与 GNU/PAX 元数据，实际解压流及 tar 结束后的排空也有界。认证尾部仍必须完整验证，达到上限不能冒充正常 EOF。
- 保留现有备份支持范围：每归档成员内容合计和单成员上限 8 GiB、成员数 100,000、路径 4096 字节、清单 1 MiB；键控配置验证上限 64 MiB。实际流预算另计合法 tar 头部、填充与长路径开销。超限拒绝加载，原归档保留。
- 主密钥最多读取 33 字节并严格检查 32 字节，不接受截断，也不自动替换已有密钥。加密封装及分帧的自有明文缓冲使用 `Zeroizing`，预留认证标签空间以避免追加标签时重新分配明文内存。

## 使用与验证

更新后沿用现有账号与资料，无需转换文件或重新登录。正常备份/检查/恢复入口不变，恢复仍创建新的私有副本，不替换活动身份库。若出现清理警告，已验证副本仍保留；不要因此删除原始保险库或重新生成密钥。

定向验证为22项Rust、6项Python和7项前端/双语检查，另有TypeScript检查；使用合成资料覆盖认证尾部损坏、暂存清理、已有邻接目录保留、GNU/PAX兼容、展开/清单/配置资源限制、31/32/33字节密钥和旧gzip/Zstd读取。源码CI、安装包审计与本机更新的最终数据另见交付核验文档。

这些改动不等于进程内所有副本均能可靠擦除，也不能阻止已取得同一用户权限并能读取密钥与归档的程序。DPAPI、新版口令派生或密钥轮换未加入本次更新；它们需要独立的兼容及恢复设计。安装/卸载验收与真实账号消息权限验证仍是独立事项。
