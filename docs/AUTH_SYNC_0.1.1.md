# 0.1.1 登录状态同步与环境核验修复

重新登录 Claude Code 后，本地授权资料与应用中保存的历史请求结果可能不同。网页能登录、本地 CLI 显示已登录，都不能单独证明保存账号的消息权限已恢复。

本次修复三个具体原因：关闭自动续杯时，原生调度器此前也跳过了账号就绪状态同步；当前账号转为保存摘要时，会丢失已有的 OAuth 到期时间与刷新资料存在性；历史授权失败、完整错误与冷却原因在同一横排反复展示，容易造成状态误解和界面溢出。

现在关闭自动续杯仍会同步本地就绪状态，但不会自动发送请求。当前与保存摘要保留已有授权元数据。每个账号分开展示简短状态、本地登录、操作、单条说明和最近尝试，等待时间改为时分秒；“允许一次恢复尝试”完成后明确显示已允许一次验证。

一次恢复许可只解除已确认的授权专属退避。真实 429、共享路由间隔和未知请求保护仍有效；保存账号、网页查询成功或本地登录可用都不会擅自清除历史消息授权阻断。缺少本地运行依赖等明确未开始验证的失败保留一次许可，实际授权拒绝仍消耗许可。

浏览器环境的未知项与账号授权分别处理。出口服务未提供机房/运营商分类时保持未知；WebRTC 使用无 STUN 的有界本地候选观察，完整收集后才能确认该有限检查结果，超时或接口失败仍为未知。只有未知项的完整报告显示“检测未完成”，明确不符项显示失败，不能把 18/20 描述为泄漏或账号封禁。

账号持有人更新后可刷新身份摘要，确认保存快照对应正确账号。如仍显示历史授权待验证，先完成该账号的 Claude Code 登录并更新保存快照，再点击允许一次验证；在窗口到期且其他门禁允许时唤醒。只有新请求的可信结果能确认消息权限或新 5h 窗口已恢复。

本次验证使用合成数据、假原生 IPC 和隔离浏览器环境，没有通过真实账号发消息、切号、轮换授权或清理浏览器资料。安装包、源码与本地更新的实际状态以当前交接文档和独立交付回执为准。
