# Claude-Local data and execution boundaries

The UI receives bounded identity display metadata, local quota summaries and operation results. Raw OAuth tokens, vault keys, cookies and proxy credentials are not serialized to the UI. Identity archives are authenticated encrypted containers; SQLite stores indexes and summaries, not credential bodies. Same-user and administrator access is not an absolute confidentiality boundary.

The default Claude workspace is managed through whitelisted files and selected JSON keys. Identity changes and destructive cleanup require the existing user confirmation, running-process checks, file snapshots and transaction/rollback logic. Personal source trees, unrelated applications and arbitrary paths are outside cleanup scope. A running identity recovery state blocks conflicting operations.

Browser data uses a separate per-identity profile under the application data root. A browser launch is an explicit action; ordinary application startup does not start it. Browser measurements use a bounded tokenized loopback session and report only the fields required for verification. Passing measurements do not establish anonymity, service acceptance, DNS or WebRTC privacy.

Manual network diagnostics contact four fixed Claude service domains without account authentication, redirects or arbitrary user-supplied targets. Companion verification may contact the documented public IP/location services when requested. Owner-approved public iKuuu/Kookeey referral links are bundled as copy-only UI content, with no recipient editor or automatic navigation. The application has no upstream updater, VPS deployment or external Skill installation workflow.

The passive Python quota collector reads Claude configuration and statusLine input. It writes only the independent external ledger and SQLite summaries, using a writer lock, atomic replacement and fresh-anchor checks. Rust consumes the ledger without replacing it with estimates. Offline inference is an estimate, not authoritative service entitlement.

The online collector uses a fixed profile GET to verify an account access credential, followed by a fixed usage GET. Archived expiry metadata alone does not reject a still-authorized credential; server authentication and identity matching remain mandatory. It never renews credentials, switches accounts or writes Claude configuration. Manual queries cover all frozen account targets with two workers and fingerprint deduplication. The optional three-minute foreground batch defaults off and pauses when hidden/unfocused. Cross-process leases, a sixty-second success cooldown and at least three-minute error/Retry-After backoff prevent duplicate and excessive requests. Only Python writes observations or metadata. Manual queries may pair with an already running managed profile to obtain live usage after eligible OAuth failures; no cookies are exported and automatic batches never navigate browsers. Missing fields retain their last valid value and independent observation times.

Every read is bound to the fingerprint displayed when requested. Native and Python reject missing or changed targets. OAuth profile account UUID, organization UUID and email must strictly match; a usage response alone does not prove token ownership. Python re-resolves the account and credential before a locked commit. The browser fallback additionally requires the exact extension Origin and a short-lived, single-use, independently paired endpoint, with account plus organization fingerprint matching. A changed target set revokes automatic batch consent; switching the current account within the same known set does not add targets. Existing current-profile metadata tickets remain invalidated on session changes. A same-account session rotation may leave an already consumed account-verified snapshot in flight, but it cannot be written to another account or organization.

Explicit CLI maintenance may check the fixed public `downloads.claude.ai` release metadata and update Claude Code through its detected installation source. Checks carry no account credentials, refuse redirects, bound the version response and have timeouts; they do not run on startup. Updates refuse active CLI processes, do not automatically end sessions or perform an uninstall, and verify the resulting local CLI status. This maintenance feature does not update Claude-Local itself.

Token statistics are separate from the quota collector. The native reader streams local Claude Code usage metadata and retains numeric counters, timestamps, model identifiers, hashed request identifiers and stable local account indexes in a private usage database. It does not retain prompts, responses or credential bodies, change Claude configuration, call OAuth endpoints or write the Python quota ledger. Ambiguous historical records remain unattributed; thinking text is not converted into an estimated reasoning-token count. Only aggregates and allowed identity display fields cross the UI boundary.

Windows paths reject links/reparse points where identity operations require regular owned files. Private storage creation specifies the current user owner and restricted ACL. Migration preserves the source, checks that relevant source programs are closed, refuses database sidecars/recovery state, verifies every copied file and database integrity, and publishes only a complete private destination.

No credentials, identity data or local configuration belong in Git, CI or build artifacts. CI runs synthetic checks on ephemeral hosts. Installer jobs are manually dispatched, use no publishing/signing secrets and upload private artifacts only. Third-party distribution terms remain separate from application data security and are documented in NOTICE.md.


Backup packages use PBKDF2 key derivation and AES-GCM envelope encryption. Full backups enforce valid SQLite integrity (v3), matching record and archive counts, and authenticated inner identity archives (manifest version 1, matching record ID, verified HMAC when present, and data/n slot completeness) with bounded member limits (up to 100,000 members, 4096-byte paths, 1 MiB manifest, and 8 GiB expanded size). Rescue packages allow preserving unverified or damaged evidence without pretending it is an authorized active vault.

Online quota proxy support is strictly limited to unauthenticated HTTP proxies using CONNECT tunnels to HTTPS targets. SOCKS proxies, HTTPS proxy schemes, and proxy authentication are rejected to prevent credentials leaks or silent direct route fallback. Runtime capability probing runs under `-E -s` without modifying environment or auto-installing external dependencies.
